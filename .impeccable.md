## Design Context

### Users
Experienced terminal users operating Lyra inside software repositories. They expect keyboard-first workflows, precise system behavior, inspectable state, and minimal ceremony. First-run success means installing Lyra, selecting a provider, storing or referencing credentials securely, and reaching a working prompt in under two minutes.

### Brand Personality
Industrial, minimal, precise. Lyra should feel calm under load, operational rather than promotional, and trustworthy because it exposes exact state and consequences.

### Aesthetic Direction
A dense terminal-native interface aligned with the existing Graphite Flywheel theme. Strong information hierarchy comes from alignment, spacing, restrained color, and exact copy—not decorative cards, gradients, illustrations, or modal-style ceremony. Provider onboarding is a short keyboard-driven sequence with advanced configuration available without hiding it.

### Design Principles
1. Keyboard first: every setup action is reachable with arrows, number keys, Enter, Escape, and visible shortcuts.
2. Time to first prompt: request only the provider, model, endpoint when needed, and credential strategy.
3. Secure by default, permissive by choice: prefer OS keychain storage, while supporting environment references and explicitly chosen plaintext configuration.
4. Show exact consequences: state where credentials are stored, which config file changes, and which provider/model will be used.
5. Dense but legible: preserve the compact Flywheel layout, use restrained accent color for focus and status, and avoid onboarding prose that does not help the next action.
